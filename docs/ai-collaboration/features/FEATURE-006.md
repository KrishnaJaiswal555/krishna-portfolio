# FEATURE-006: Skills and résumé

- Status: In progress
- Next step: Browser pass. Nothing visual has been observed in any phase.

## Scope
- Goal: Bring the Skills section up to the cinematic treatment the other
  sections already have, and give the résumé a real place on the page rather
  than a bare unlabelled button.
- In scope: reveal hooks across the Skills section, the résumé block, skill
  group separation, the experience line, and three new content assertions.
- Out of scope: proficiency levels, ratings, years-per-skill or any ranking —
  **no verified data exists for any of it**, and inventing it is exactly what
  the brief forbids. Skills are listed, not scored.

## What Was Tried

| Approach | Result |
|---|---|
| Skill proficiency bars / star ratings | **Rejected outright.** There is no source for a proficiency number. Any bar drawn would be fabricated, and a recruiter reading "Python 90%" would be reading something invented. |
| Sort skills by strength | Rejected for the same reason — ordering implies ranking, and no ranking data exists. Groups stay in their authored order. |
| A fifth canvas for this section | Rejected. The particle set is closed at four configurations; a fifth would dilute the motif for a section that does not need it. |
| **Reveal hooks + a hairline rule per group** | **Chosen.** Skills was the only section with no reveal hooks at all, which made it the one place the cinematic treatment simply stopped. |
| Leave the résumé as a bare `<p>` + button | Rejected. An unlabelled download button gives no idea what it contains. It is now a titled block with a one-line description. |

## What Worked
- Reveal hooks on the section heading, the experience and certification
  blocks, and each generated skill group. `renderSkills()` sets
  `data-reveal` on the blocks it creates; `reveal()` runs after every render
  function, so generated hooks are picked up exactly as static ones are.
- A hairline top rule per skill group, so five tag clouds read as five
  categories rather than one undifferentiated field of pills.
- The experience line now prints `location`, which was already in
  `content.js` and had never been rendered. It is part of how an employment
  entry reads on a CV.
- The résumé block stays entirely hidden unless the PDF is actually present.
  A download control that 404s is worse than no control.

### Applying the #0007 lesson forward
Printing `e.location` silently promoted it to a **required** field: a missing
one would render the literal string `undefined` rather than failing. That is
the same silent-absence trap that hid the missing project architecture for
five phases. Rather than wait for it to bite, three assertions were added in
the same change — covering experience, certifications and timeline entries —
so every field a renderer prints is now asserted to exist.

The content check went from 8 to 11.
